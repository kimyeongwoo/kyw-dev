Then use one `git update-ref --stdin` transaction: `start`, old-value CAS updates for both `refs/remotes/origin/main` and `refs/heads/main`, an immediate direct-remote and GitHub `N` re-read, `prepare`, and `commit`. Every stage begins by revalidating the identities established above and every earlier stage. The fixed order is:

Derive the selected Task's exact verified path set from its scope, final repository diff, Test evidence, documentation impact, and any valid predecessor-only checkpoint transition. Reject ambiguous ownership, missing/type/mode drift, unexpected generated bytes, or overlap that cannot be separated from user work.

Never use broad staging, cleanup, reset, or destructive recovery. If pre-existing staging or path overlap prevents proof, block.

Create one ordinary selected-Task commit only if no matching completed commit already exists. Record its exact SHA and parents. Do not amend or manufacture a replacement on resume.

### 2. non-force push

Before this first external mutation, prove that the committed selected head contains the hardened exact-SHA workflow contract and that GitHub reports its exact workflow ID, name, path, and active state. ### 3. non-draft PR
